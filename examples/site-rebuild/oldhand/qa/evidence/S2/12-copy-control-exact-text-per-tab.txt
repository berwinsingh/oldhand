  navigator.clipboard.readText() -> NotAllowedError: Failed to execute 'readText' on 'Clipboard': Read permission denied.
  (blocked in this browser pane, so the brief's fallback applies: the aria-label of the control, which carries the exact text.)
Extra evidence beyond the fallback: before clicking, a small observer was put on the page that records what the page's own copy handler sends
  (a wrapper that logs the argument of navigator.clipboard.writeText and then calls the original, plus a document "copy" event listener that logs the selection).
  navigator.clipboard.writeText also threw "NotAllowedError ... Write permission denied" in this pane; the page then used its textarea + document.execCommand("copy") fallback,
  and the "copy" event fired with the selected text. The recorded values are given below. The button label changed to "Copied" after each click (see screenshots 02, 03, 05).
  The page does not show an error when writeText is denied (it falls back silently). That is the page's designed behavior, not a failure.
