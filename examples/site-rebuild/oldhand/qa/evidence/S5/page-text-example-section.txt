Root cause

(traced + observed, rca.md) write_batch (importer/batches.py) was retried as a unit by with_retries but was not atomic: it committed the rows before the progress update, and any failure inside its transaction, the COMMIT included, left the transaction open on the shared connection, so the retry's INSERTs joined it. The user's "no idempotency key" is true but not the cause; an atomic, rolled-back batch makes the retry safe without a schema change. Observed on Python 3.9.6: with conn: does not roll back a failed COMMIT, so the fix rolls back explicitly.
