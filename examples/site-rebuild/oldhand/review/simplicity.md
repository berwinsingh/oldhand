# simplicity lens

## Findings

- [medium] site/src/App.jsx:73-80 and 351-374: the model routing table is typed in by hand, a second copy of `skills/oldhand/references/orchestration.md`, which calls itself "the one file to update when lineups change". It contradicts the page's own rule in site/AGENTS.md:3-5 ("imported, never copied"), and the file already has the parser for it. `Table` (App.jsx:107-127) and `section()` (App.jsx:82-88) are written for this job and are used only for the report. The copy is already abridged: the version numbers are gone ("Fable, else Opus" against "Fable 5.1 ... Opus 5.5", "Composer" against "Composer 2.5", "Gemini Pro" against "Gemini 3.1 Pro"), and the Devin Desktop row is missing. The "as of October 2026" date at line 358 is typed in too. Scenario: the next lineup change edits orchestration.md as instructed, nobody touches App.jsx, and the live page keeps showing the old table under a hard-coded "October 2026" date. Fix: add `import orchestration from "../../skills/oldhand/references/orchestration.md?raw"`, delete the `models` array and the hand-written `<table>`, and render `<Table text={section(orchestration, heading)} columns={["host","lead","worker","scout"]} />`. This removes about 17 lines. Match the heading by prefix (`## Current models per host`) and take the date from it. I ran `section()` and the row parsing from App.jsx against the real file in a temp folder. With the exact heading string it returns 8 rows (header plus 7 hosts) and the right four columns. After the heading date is edited to "November 2026", an exact-string match returns "" and `Table` renders nothing, silently, so a prefix match is required. Confidence: high

- [low] site/src/App.jsx:163-174 and 180-187: install-tab persistence and a `?agent=` URL parameter. Neither is in the contract (AC2 asks only for tabs, commands, a copy control, the line to type, version and date). The old page had neither (`git show HEAD:site/src/App.jsx` has no install-tab state), and no link on the page uses `?agent=`. It costs about 12 lines, a second localStorage key (`oldhand-install-tab`) and a try/catch in `choose`. Scenario: a visitor who once clicked "Git clone" lands on that tab on every return visit and never sees the default "Any agent" route first. Fix: `const [tab, setTab] = useState("any")`, and if the deep link stays, use `const q = new URLSearchParams(location.search).get("agent"); useState(installs.some(i => i.key === q) ? q : "any")`. Drop the storage code and make `choose` plain `setTab`. Note that plan.md S2 lists `?agent=codex` and a bogus `?agent=` as scenarios, so the deep link has plan backing but no contract backing; the storage persistence has neither. Keep the arrow-key handler (lines 189-197); it is the ARIA tablist pattern and belongs to accessibility. Confidence: high

- [low] site/src/styles.css:14-34: dead theme-override block. `data-theme` is never set anywhere (`grep data-theme site/src site/index.html` hits only the two CSS selectors), so `:root[data-theme="dark"]` (lines 26-34) repeats the dark tokens a second time for a switch that does not exist, and the `:not([data-theme="light"])` guard on line 15 is a guard against nothing. Scenario: someone edits a colour for dark mode in the media block and the dead copy now disagrees, with nothing on the page that could ever select it. Fix: keep only `@media (prefers-color-scheme: dark) { :root { ... } }` and delete lines 26-34. This removes 9 lines. `color-scheme: light dark` on line 11 already covers the native controls. Confidence: high

- [low] site/src/App.jsx:114: `Table` takes an optional `columns` and keeps a branch for when it is absent (`: rows[0].map((_, i) => i)`). The only caller (line 330) always passes it, and the fix for the models table also passes it. Dead branch. Fix: make `columns` required and drop the ternary. Confidence: high

## Checked and found fine

- Contract line "Out: any new dependency, a Markdown renderer": the hand-rolled `section`/`inline`/`List`/`Table` (App.jsx:82-127, about 45 lines) is the lazy choice that respects it. `package.json` gains no dependency and loses `@phosphor-icons/react`, and the lockfile change is the removal only (`git diff -- site/package.json site/package-lock.json`).
- `site/src/analytics.js` is the old code from App.jsx moved out and given optional `win`/`doc`/`storage` parameters. The test passes fakes through those, so the parameters are used, not speculative. The test file is 5 short tests and no framework, which is proportionate for R3. The `loadAnalytics` export is used only inside the file but costs nothing.
- Tab arrow-key handling, `aria-selected`/`tabIndex`, the `execCommand` fallback in `CopyButton`, and the try/catch around storage are accessibility or error handling; the lens says not to trim them, and I did not.
- The stage list (App.jsx:59-71) is hand-written one-liners, which is right: the SKILL.md `description` fields are long trigger text for the agent, not one-line summaries, so nothing to slice. Each line links to its SKILL.md.
- Hard stops, example verdict, criteria table, root cause and "Not verified" are sliced from the imports (App.jsx:247-255). The split-then-join of the hard-stops intro (line 248, 318) is roundabout but defensive and tiny.
- `site/vite.config.mjs` adds only `fs.allow: [".."]`, which the `?raw` imports from outside `site/` need in dev. The build output is 252K (`index.html` 3.3 kB, CSS 5 kB, JS 230 kB) after removing the 2.9 MB of PNGs.
- CSS: every class in `styles.css` is used by `App.jsx` or `index.html` (checked by hand against the JSX). The stylesheet fell from about 1,365 changed lines to 456. Minor leftovers (`list-style: decimal` on an `ol`, `.tested` declared in two rules) are style nits and not reported.
- Fonts via a preconnected Google Fonts `<link>` with a system fallback stack is the contract's stated default (contract.md "Open questions"), so not a simplification target for this lens.
- `site/AGENTS.md` and the README install hunks are prose. The README install table repeats the site's tabs, but the README has to carry its own copy for GitHub readers.
- No debug prints, commented-out code or leftover files in the changed site files. Deleted assets are gone from the working tree.
