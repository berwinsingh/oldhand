# security lens
## Findings
- [low] site/vite.config.mjs:17 (with :13): `fs: { allow: [".."] }` widens the dev server's file allow-list from `site/` to the whole repo root while the config still binds `host: "0.0.0.0"`. Scenario: a developer runs `npm run dev` (what site/AGENTS.md tells them to do) on shared Wi-Fi; anyone on the LAN requests `http://<lan-ip>:5173/@fs/<abs repo path>/.oldhand/<task>/...` and reads the gitignored task folders (contract, ledger, pasted ticket text) and any other untracked file at the repo root. Vite's host check lets IP-literal Host headers through (vite 6.4.2 `isHostAllowedWithoutCache`, dep-Dq2t6Dq0.js:32180), so `allowedHosts: ["terminal.local"]` does not stop it. Shown on the running :4180 server (started with `--host 127.0.0.1`, so loopback only): `GET /@fs/Users/berwinsingh/Documents/oldhand/.oldhand/site-rebuild/review/brief.md` -> 200, same with `Host: 192.168.1.50:4180` -> 200; `.git/config` -> 403 (Vite's default deny), `../../.zshrc` -> 403. Dev server only; the built site is unaffected. Fix: allow only what the page imports, `fs: { allow: [".", "../skills", "../examples", "../.claude-plugin"] }` (entries resolve against the Vite root, dep-Dq2t6Dq0.js:38837/38904; "." keeps site/node_modules reachable). I did not run the narrowed config (the brief says not to start a server). Confidence: high on the exposure, medium on the exact replacement list.
- [low] site/src/App.jsx:141 and :144: the clipboard fallback ignores the return value of `document.execCommand("copy")` and calls `setCopied(true)` whether or not anything was copied. Scenario: the Clipboard API rejects (page in an iframe without clipboard-write, permission denied) and `execCommand` returns false (Safari iOS, or a blocked selection) -> the button says "Copied", the clipboard still holds whatever the visitor had before, and they paste that into a terminal expecting the install command. The strings copied and shown are the same `text` (App.jsx:157-158), so this is a stale-clipboard risk, not a hijack. Overlaps the correctness lens. Fix: `const ok = document.execCommand("copy");` and show "Press Ctrl+C" (or leave the label as "Copy") when `!ok`; move `textarea.remove()` into a `finally`. Confidence: medium (traced, not run; needs a browser where both paths fail).
- [low] site/index.html:16-21: Google Fonts (CSS from fonts.googleapis.com, woff2 from fonts.gstatic.com) loads on every visit before any analytics choice, so every visitor's IP, user agent and the page origin go to Google while the footer says "Analytics are off." (App.jsx:409). Observed in the browser with no stored choice: `performance.getEntriesByType("resource")` lists fonts.googleapis.com and two fonts.gstatic.com woff2 files, and no googletagmanager entry. This is not a regression: HEAD loaded Google Fonts through a CSS `@import` (HEAD styles.css:1), and the diff only moved it to `<link>`. It does not break AC5 or R3 (those are about gtag) but it undercuts the page's own opt-in framing. Fix: self-host the two families (copy the woff2 files into site/public and write `@font-face`), or fall back to the system stack. Confidence: high that it happens; low that it matters to the criteria.
- [low] site/src/App.jsx:17 (note at :20): the Any-agent command is `npx skills add berwinsingh/oldhand --skill '*' -g` with no version, while the line under it says it was tested with "skills 1.7.2". Scenario: a visitor runs it months later, npx fetches the then-current `skills` package, which is a different program from the one tested, and it installs executable skills globally (`-g`). Fix: either `npx skills@1.7.2 add ...` (the version actually tested) or reword the tested line to "latest at the time". Confidence: medium (the trade-off is real: a pin goes stale).

## Checked and found fine
- `?agent=` (App.jsx:166-167): the value goes through `URLSearchParams.get` and is used only as an `Array.includes` membership test against the four literal keys; anything else falls through to the stored tab or the first tab. It is never rendered, never written to storage, never put in an `href`. Browser check with `?agent=<img src=x onerror=window.__xss=1>`: no element injected, `window.__xss` stays undefined, the page used the stored tab. `__proto__`/`constructor` cannot match an array of strings.
- localStorage (App.jsx:168, :183; analytics.js:7-18): two namespaced keys. Both reads validate against an allow-list (the tab keys, "granted"/"denied") and every access is in try/catch, so a poisoned or blocked store reads as "no choice" (unit test "junk or a throwing store reads as null"). Same-origin note: `berwinsingh.github.io` is shared with the owner's other Pages projects, so a sibling page could write these keys; that needs access to the owner's own pages.
- Build-time imports in the DOM (App.jsx:2-4, :247-256, :316-348, :401): `skillText`, `reportText` and `plugin.version` reach the DOM only as React text nodes or through `inline()`, which builds `<code>` elements from backtick spans. Grep of site/src and site/index.html finds no `dangerouslySetInnerHTML`, `innerHTML`, `insertAdjacentHTML`, `document.write`, `eval`, `new Function`, `target="_blank"` or `window.open`. No `href` is built from imported text (every href is `REPO`/`BLOB` plus a literal or a `stages` name), so `[x](javascript:...)` in a markdown file would render as literal text. Imported files contain no `<script>`, `<iframe>`, `javascript:`, absolute local paths, e-mail addresses or key-shaped strings (grep of SKILL.md, report.md, plugin.json), and the same greps on the built bundle site/dist/client/assets/index-Cnbwz_nJ.js find none. No source maps in dist/client. plugin.json carries only name, version, description, author, homepage, license and keywords (the default import ships the whole object).
- Third-party loads: the only external origins in the built bundle are googletagmanager.com (gated, see next bullet) and the namespace/error-URL strings from React; index.html adds only the Google Fonts hosts (see finding 3). No other CDN, no inline third-party script, no iframe. The G-75YW6HE9FT measurement id is public by design (already at HEAD) and is not a secret.
- R3 / analytics gating: ran `node --test` on analytics.test.mjs in a temp copy, 5 of 5 pass. In the real app with no stored choice: `script[data-oldhand-analytics]` count 0, `typeof window.gtag` "undefined", `window.dataLayer` null, no googletagmanager resource entry; footer reads "Analytics are off." (`useState(readAnalyticsChoice)` is called with no arguments, so it reads `window.localStorage`). With `document.head.appendChild` stubbed so no real request could leave, clicking the footer toggle produced consent default (all four denied), consent update granted, js, config, and exactly one script src `https://www.googletagmanager.com/gtag/js?id=G-75YW6HE9FT`; toggling off pushed `consent update analytics_storage: denied` and stored "denied". I removed the stored key afterwards and reloaded; the shared tab is back to no stored choice. `script.src` is built only from a constant id. Strict-mode double effect is safe (`loadAnalytics` checks for the marker script).
- Clipboard (App.jsx:129-161): the fallback textarea holds only page-controlled text, is created and removed synchronously, and the copy fires only from a click handler. The string copied is the same variable that is displayed, so no display/copy mismatch.
- Install commands: no `curl | sh`, no `sudo`, no tokens or credentials, no URL other than github.com/berwinsingh/oldhand. The commands are static literals.
- CI screenshot step (.github/workflows/pages.yml:34-66, unchanged by the diff): preview server binds 127.0.0.1, Chrome runs on a fresh profile so no stored consent exists and gtag cannot load during the og-image screenshot; the only new external fetch it triggers is the Google Fonts one noted above. The deployed artifact is `site/dist/client` only (index.html, hashed assets, favicon, og-image), so `dist/.openai` and `dist/server` are not published.
- Dependencies: the diff removes `@phosphor-icons/react` from package.json and the lockfile and adds none.
- Not checked: whether opting out after opting in removes the `_ga` cookies (needs a live GA hit; I deliberately sent none to the owner's property); a CSP meta tag or SRI (GitHub Pages cannot set headers and dynamic gtag cannot take SRI, so left as a follow-up, not a defect); worker/index.js and prepare-sites-build.mjs (unchanged); pages.yml workflow-level `pages: write` / `id-token: write` on the build job (pre-existing, untouched, so a follow-up).
