## Findings

- [medium] .github/workflows/pages.yml:5-8: the deploy trigger is `paths: site/**` and `.github/workflows/pages.yml`, but the page imports `skills/oldhand/SKILL.md`, `examples/csv-import-dupes/oldhand/report.md` and `.claude-plugin/plugin.json` from outside `site/` (site/src/App.jsx:2-4). Scenario: a release commit on main bumps `.claude-plugin/plugin.json` to 2.0.1, or edits a hard stop in `SKILL.md` -> Pages does not run -> the live header still says `v2.0.0`, "What it will not do" and the Copy button still carry the old skill, while the text says the skill was "imported from the repository when this page was built". The page drifts from the files AC1/AC6 say it mirrors. Fix: add `skills/oldhand/SKILL.md`, `examples/**` and `.claude-plugin/plugin.json` to the `paths` list (trigger only; the build and screenshot steps stay unchanged, so R2 holds). Confidence: high (traced; not run on GitHub)

- [medium] site/src/App.jsx:82-88, 247-255 (rendered at 316-318, 331-335): the slicing fails silently when a heading moves or is renamed, and the build still passes. Scenario: rename `## Hard stops` in SKILL.md to `## Hard rules`, and `## Root cause` / `## Not verified` in report.md to anything else -> `section()` returns "" -> reproduced in a temp copy: `npm run build` exits 0, and the page ships "What it will not do" with the intro sentence only and zero list items, plus "Root cause" and "Not verified" headings over an empty `<p>` and an empty `<ul>`. The slicing runs in the browser at render time, not at build time, so nothing can fail the build, and `npm test` / `npm run test:sites` do not look at it (and no CI job runs `npm test` at all; pages.yml only builds). The hard stops disappearing is the worst case, since AC1 says they are sliced from the import. Fix: add a check to the `build` script, for example `node scripts/check-sources.mjs` that reads the three files and asserts the `## Hard stops` section has 10 numbered items, `report.md` has `| criterion` rows, `## Root cause` and `## Not verified` are non-empty. Throwing inside `App` instead would only blank the live page, not fail the build. Confidence: high (reproduced)

- [low] site/src/App.jsx:252 and 96-105: sibling edge cases in the same slicing code. (a) `lines.slice(first, lines.findIndex((line, i) => i > first && !line.startsWith("|")))` gets -1 when the criteria table is the last thing in the file, so `slice(first, -1)` silently drops the last criterion row. Today `report.md` has text after the table (line 14), so it does not fire. (b) `stopsRest.join("\n\n")` goes to `List`, which ignores any non-bullet line before the first bullet, so a second intro paragraph added to the hard-stops section vanishes; an indented sub-bullet is glued onto the previous item as plain text. Fix: use `end < 0 ? lines.length : end`; let the source check above also assert the item count. Confidence: medium (traced, not run)

- [medium] site/src/App.jsx:131-146: `CopyButton` reports "Copied" when nothing was copied. Scenario: `navigator.clipboard.writeText` rejects (or is undefined on plain http) and the `document.execCommand("copy")` fallback returns `false` (iframe without clipboard permission, locked-down browser) -> reproduced with both stubbed: the button shows "Copied" for 1.6 s and nothing is on the clipboard. The return value of `execCommand` is never read. AC2 asks for a working copy control; a failure that looks like success sends the visitor to paste a stale clipboard into their terminal. The fallback also leaves keyboard focus on `<body>` (reproduced: `document.activeElement` was BODY after the click), so a keyboard user loses their place. Fix: `const ok = document.execCommand("copy")`; on failure show "Press Ctrl+C" / select the text instead of "Copied"; call `event.currentTarget.focus()` after `textarea.remove()`. Confidence: high for the false success (reproduced); medium for the focus loss (reproduced with stubs, real browsers differ on whether `select()` focuses)

- [low] site/src/App.jsx:148-149, 158: screen-reader feedback on the copy controls is weak. The button has a fixed `aria-label` ("Copy: <command>"), so its accessible name never changes to "Copied"; the only announcement is a `aria-live` span nested inside the button, and a button's children are presentational, so several screen readers will not announce it. For the git-clone tab the label is the whole three-line script, read out as the button's name. Fix: label it "Copy install command" (or "Copy command 1 of 2" on the Claude tab) and put the status in a sibling `<span role="status">` outside the button. Confidence: medium (traced against ARIA rules, not tested with a screen reader)

- [low] site/src/App.jsx:189-197: the tablist handler calls `preventDefault()` for every ArrowLeft/ArrowRight, including with Cmd, Alt, Ctrl or Shift held. Scenario: focus is on a tab and the visitor presses Cmd+Left (macOS) or Alt+Left (Windows/Linux) for browser Back -> reproduced: both events come back `defaultPrevented: true`, and the tab selection also moves. Home/End are not handled (optional in the tabs pattern). Fix: `if (event.metaKey || event.altKey || event.ctrlKey || event.shiftKey) return;` at the top; add Home/End if wanted. Confidence: high (reproduced)

- [low] site/src/App.jsx:348, site/src/styles.css:364-372, 240-246, 320-327: scrollable regions that a keyboard-only visitor cannot reach. `pre.skill` has `max-height: 70vh; overflow: auto` and no `tabindex` (reproduced: `tabindex` null, `scrollHeight > clientHeight`). Chrome and Firefox make such a scroller focusable, Safari does not, so in Safari the keyboard cannot scroll the 300-line SKILL.md box. The same applies to `.command pre` (x overflow) and to the tables, which use `display: block; overflow-x: auto` on the `<table>` itself; that drops the table role in Safari/VoiceOver, so the criteria table is read as plain text. Fix: `<pre className="skill" tabIndex={0} aria-label="SKILL.md source">`; put each table in a `<div className="scroll" tabIndex={0}>` with the overflow and leave `table` as `display: table`. Confidence: medium (Chrome behaviour measured; Safari from known behaviour)

- [low] site/src/analytics.js:55-63: turning analytics off stops hits but leaves the GA cookies behind. Scenario: visitor clicks "Turn on anonymous Google Analytics", then "Turn it off" (or opts out on a later visit) -> reproduced: after the toggle and after a reload with the stored "denied", `document.cookie` still holds `_ga` and `_ga_75YW6HE9FT` (GA sets them for up to two years), while the footer says "Analytics are off." No gtag script loads and no hit is sent, so R3 holds; the gap is only that "off" leaves identifiers on the device. Fix: on "denied", expire `_ga` and `_ga_<id>` on the current host, or word the footer "No analytics are sent." Confidence: high (reproduced)

- [low] site/src/styles.css:453-456 (with .github/workflows/pages.yml:55-64): the social-preview image crops the hero mid-element. Scenario: the workflow's own Chrome flags (`--window-size=1200,627 --virtual-time-budget=3000`, run locally against the built page, 93 KB PNG, step succeeds) -> the hero is 834 px tall under a 56 px header, `html.social-preview` clips at 627 px, so the shared card shows the install box cut off in the middle of the second "Then, in ..." row. R2 itself (the hook renders at 1200x627, the file is non-empty) holds. Fix: add `html.social-preview .then, html.social-preview .note, html.social-preview .tested { display: none; }` after styles.css:453 so the box ends at the command. I rendered in dark scheme (my OS setting); the CI runner renders light, and the height is the same. Confidence: high (reproduced locally; not run on the runner)

- [low] site/src/App.jsx:51: the Git clone tab says "git 2.x", which is not a tested version; AC2 asks for the tool version and date tested, and the other three tabs give exact versions. Scenario: a visitor on git 2.20 or on Linux cannot tell what was tested. Fix: replace with the output of `git --version` from the test run. Confidence: medium (overlaps the contract lens; the recorded evidence was not re-checked)

## Checked and found fine

- Temp copy (`npm ci`, then `npm run build`, `npm test`, `npm run test:sites`): build exits 0 and leaves the three dist files; 5 analytics tests and 4 sites tests pass. The `?raw` imports from outside `site/` resolve in `vite build` with no extra config, and pages.yml checks out the whole repo, so they resolve on the runner too.
- R3: fresh load (empty storage) on the built page and on the dev server: no `googletagmanager` script, no `dataLayer`, no `gtag`, no request to it; `dist/client/index.html` has no gtag reference; the only gtag string in the bundle is inside `loadAnalytics`. After a click on the footer toggle: `consent default` (all four denied), `consent update` (analytics_storage granted), `js`, `config`, one script, storage `granted`. Turning off: `consent update` denied, storage `denied`. Reload with `denied`: no script, footer "Analytics are off." Turning on twice does not inject a second script (marker lookup), which also covers the React StrictMode double effect in dev.
- `analytics.js` storage access is wrapped in try/catch for read, save and `readTab`/`choose`; junk values read as null; a toggle from null, denied or granted goes to the right next state (App.jsx:241-245).
- Slicing on the current content: 10 hard stops (the last one ends "...where it lives."), 6 criteria rows with the five requested columns, verdict "Verdict: VERIFIED", 4 "Not verified" items, root cause text starts at "(traced + observed, rca.md)". The regexes tolerate the multi-line list items and the pipe-free cells in the committed report.
- Tab switcher: roving `tabindex`, `aria-selected`, `aria-labelledby` pointing at the live tab, ArrowRight moves selection and focus together and wraps (reproduced); the dangling `aria-controls` on inactive tabs is allowed while `aria-selected="false"`; the panel holds focusable Copy buttons, so it needs no `tabindex`. `?agent=` wins over the stored tab and falls back to the first tab on junk or blocked storage.
- Copy happy path writes the exact `text` / `skillText` value (blocks are keyed by their own text, so the Claude tab's two prompts are two separate controls).
- `?social-preview=1`: the inline script and CSS in `site/index.html` are unchanged apart from the removed `.analytics-consent` rule, which no longer has an element to hide; the page loads at 200 under the workflow's `curl` probe and screenshot flags.
- pages.yml is unchanged by the diff.
